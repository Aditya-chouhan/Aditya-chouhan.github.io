Operating rigor

What changed after the systems met reality

The strongest proof is not a green demo. It is finding the failure, understanding it, fixing it and leaving a receipt.

Salesforce: made asynchronous behavior testable, not merely green.

The first real Apex run returned 19/20 because scheduled and batch behavior raced under Test.stopTest(). I isolated both paths into deterministic tests; the re-run finished at 20/20 with 96% org-wide coverage.

Inspect the test evidence →

n8n: proved the fallback worked, then fixed the classifier.

A forced failure generated a page-intent payload through the conservative default, but n8n rewrote the error name and the code defect landed as “unclassified.” I updated the rule to the runtime payload the workflow actually received. External notification delivery is not part of this build.

Inspect the forced-failure receipt →

Removed a stale metric from contact-facing output.

A live-data demo still pasted a hard-coded +183% into outreach. I moved the metric to the same dated source-of-truth function used by scoring, so the claim now recomputes with each run.

Inspect the correction →

Made the documented setup genuinely reproducible.

The CRM lifecycle repository used Python 3.10+ syntax without declaring that minimum. I fixed the compatibility and setup documentation, then verified that regenerated outputs were byte-identical.

Inspect the reproducibility fix →

Added uncertainty and sample concentration to my own metric.

Groundtruth's 60.5% precision was correct, but its confidence interval and 65% single-repository concentration changed how the result should be read. I published both caveats in the evaluation harness and ran the checker across this portfolio.

Inspect the self-audit →
